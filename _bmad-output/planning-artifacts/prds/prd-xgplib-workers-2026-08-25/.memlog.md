- (decision) Core value: Modern, intelligent digital catalog for Xbox Game Pass games to replace poor official UI
- (decision) Data sources: Microsoft APIs (availability to be verified) combined with public IGDB API for rich metadata
- (decision) Storage: PostgreSQL using JSON fields for flexible schema (initial fields: title, photo, screenshots, descriptions, genre, age rating)
- (decision) Stakes: Personal/hobby project (start)
- (decision) Working mode: Coaching path
- (decision) Project Scope: This PRD is specifically for the 'workers' component (data ingestion and synchronization), one of three planned pieces (Front-end, Back-end API, Workers).
- (decision) Working mode refinement: Capability-first (Vision + Features) selected due to the headless/backend nature of the worker component.
- (decision) Trigger: Scheduled execution (Cron)
- (decision) Resilience: Implement retry and circuit breaker. If it fails, log/skip the game and continue.
- (decision) Update Strategy: Soft delete (mark as inactive) for games leaving the catalog, preserving historical data.
- (decision) Matching Strategy: Initial exact match by name. Failures handled manually (logged for later resolution).
- (decision) Source of Truth: IGDB is ALWAYS the source of truth for metadata. Microsoft APIs used strictly for catalog state (availability by region, platform, plan).
- (decision) Pipeline flow: Pull MS Catalog -> Match by name in IGDB -> Store rich metadata from IGDB + availability flags from MS into Postgres.
- (event) Initial PRD drafted
- (decision) Cron schedule updated: Runs every 1 hour (instead of daily)
- (decision) Microsoft APIs: Public APIs exist, exact endpoints to be discovered during development/research
- (decision) Manual resolution: Handled via direct SQL scripts in the database, no admin UI required for V1
- (event) PRD finalized
