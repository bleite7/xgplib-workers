Critical

C-1 critical — The shared entity has no identity, no conflict target, no transaction boundary

Shared root cause: rubric H5 · adversary C1 · adversary C5.

Stories 1.3 and 4.1 can each be written compliantly and still disagree about what a game is. Story 1.3’s idiomatic Game(id: UUID, product_id: str) plus Story 4.1’s ON CONFLICT (id) upsert means a re-hydrated entity carries a fresh uuid — the hourly run re-inserts the same Microsoft product forever, while Story 4.1’s own test passes because it saves entities it created itself. The compensating UNIQUE(product_id) instead pushes an IntegrityError out of the adapter with no AD-5 translation path.

AD-4 describes mutation in the singular, so for e in entries: repo.save(e) is the most literal reading: a crash at item 2,500 leaves a half-migrated catalogue that C-2’s deactivation path turns into mass removals.

Fix: one AD fixing the canonical identity (upstream product id; surrogate UUIDs forbidden; UNIQUE(product_id)), the upsert contract, the unit-of-work boundary per run, and the migration tool.

C-2 critical — Availability cannot be expressed, and two mutation paths can delete the catalogue

Shared root cause: adversary C2 · adversary C4 · rubric M6.

FR-1.1 requires market × platform (PC/console/cloud) × plan. Story 2.1 returns ids per endpoint; Story 4.2 flips one boolean. A title leaving Console while still on PC is deactivated. The reciprocal reading (union the slices) is equally compliant and makes “added” unobservable. The entity has no room for {console: yes, pc: no, market: de-DE}.

Worse: Story 4.1 sets active, Story 4.2 bulk-deactivates ids absent from the fetch. A failed hydration batch under NFR-1 (“skip gracefully”) yields a smaller catalogue → mass false soft-delete, no exception raised, AD-5 satisfied.

Fix: availability as a set of Availability(market, platform, plan) value objects in its own table; no scalar is_active; “soft-deleted” = empty availability set; transitions applied once per run from the union of all slices; deactivation gated on fetch completeness; a run lock.

C-3 critical — The JSONB column has two uncoordinated writers

Ingestion stores {"raw_microsoft": …} (required by Story 3.3); enrichment replaces the whole column with IGDB keys. For matched titles the raw payload is destroyed; it survives only on unmatched titles — precisely the population Story 3.3 tests. AD-7 prevents the domain from naming the shape (Pydantic DTOs must live in infrastructure), so nothing can validate it. Key-name drift between writers means no consumer can read the column without knowing who ran last.

Fix: namespaced merge-on-write document — raw (Microsoft, write-once) and enrichment (IGDB, replaceable) — one mapper in infrastructure, persistence merges by namespace key and never replaces the column; dropping a namespace you do not own is a domain error, tested.

C-4 critical — The spine governs no system seam; Deferred claims otherwise

Shared root cause: rubric C1 · rubric C2 · rubric H8.

All seven ADs are about how Python code is arranged. No AD names a component, port, or rule for the two-step Microsoft extraction, IGDB enrichment, change detection, upserts/soft-deletes, or hourly execution — Stories 2.1 and 3.1 can pick different HTTP clients and retry styles and both stay canonical.

The operational envelope is entirely silent — deployment target, environments, PostgreSQL provisioning, what tests run against, how secrets arrive, where the unmatched-title log goes — while ## Deferred says “None explicitly deferred”. The live symptom already exists: .gitignore has no .env pattern and that item sits in deferred-work.md instead of the spine.

Fix: ADs for external integration, resilience, persistence, execution/scheduling, configuration & secrets, operations, and testing — each Binds: citing CAP-/FR-/NFR- IDs — plus a Capability → Architecture Map and a populated ## Deferred.

C-5 critical — The stack is asserted, not researched, and two implied defaults moved

Shared root cause: tech-currency C1, C2, H1–H5, M2–M3.

No version, no Python baseline, no source anywhere; the memlog shows the stack arriving as a user direction and leaving as a decision with no lookup. Independently spot-checked during this validation:

  • SQLAlchemy 2.1.5 (2026-10-16) is the current default install; 2.1.0 was the first production release (2026-09-24). greenlet is no longer installed by default (breaks async unless sqlalchemy[asyncio]), and postgresql:// now resolves to psycopg 3.
  • httpx has had no stable release since 2024-12-06; the maintained continuation is httpx2 (Pydantic fork, 2.13.1, 2026-09-23).
  • AD-2’s DI container is unnamed in a live four-way choice — dependency-injector 4.49.1, dishka 1.10.1, punq 0.9.0, injector 0.24.0 — and the PyPI name python-dependency-injector is an unrelated 1,870-byte stub.

Fix: add a ## Stack table (pin / role+layer / verified date), reduce AD-6 to a pointer at it, and name the DI container with its distribution name and composition-root path.

High

  • H-1 Sync vs async undecided — fixes every port signature, the driver (Session vs AsyncSession) and the client (Client vs AsyncClient). An hourly network-bound worker reads naturally as async.
  • H-2 Port ownership contradictory — AD-3 says domain-defined; the diagram and README put ports in application. Both placements pass the shipped contract, so the machinery cannot detect the divergence.
  • H-3 AD-2 and AD-7 cannot both be satisfied as written — mainstream containers need markers on classes that live in application, which AD-7 forbids. Name the container, put the composition root in infrastructure, require plain constructor injection in use cases.
  • H-4 Resilience has no AD although NFR-1 is a hard constraint in four artifacts: where retries/circuit breakers live, which library, where thresholds come from, what “skip gracefully” means for the use case.
  • H-5 AD-7 is not mechanically enforceable as written — no “any external” wildcard; forbidden_modules must be exact top-level names, and include_external_packages is a top-level session option, not a contract key. The spine’s phrasing invites a config import-linter rejects.
  • H-6 AD-5 has no retryable-vs-permanent taxonomy — an IGDB outage is indistinguishable from a no-match, and nothing requires adapters to translate third-party exceptions inward.
  • H-7 Entrypoints may call repositories directly — infrastructure is one layer and AD-4 binds only use cases.
  • H-8 No migration tool named while Epic 1 promises migrations.
