## Intent

**Problem:** The repository holds planning artifacts but no Python project at all — no `src/` layers, no packaging, no linter, and no mechanical guard stopping domain/application code from importing infrastructure. Without this, the hexagonal dependency rule erodes from the first feature written.

**Approach:** Create a uv-managed Python 3.12 project with flat `src/domain`, `src/application`, `src/infrastructure` layers, Ruff for lint/format, an import-linter layering contract enforcing the inward dependency rule, a pytest scaffold, and a CI workflow running all three.

## Boundaries & Constraints

**Always:** Dependency rule points inward — `infrastructure` may import `application` and `domain`; `application` may import `domain`; `domain` imports neither. Layers live at exactly `src/domain`, `src/application`, `src/infrastructure`. Ruff is the single lint/format entrypoint (PEP-8). Layer boundaries are enforced mechanically by import-linter, not by convention/review alone. `requires-python = ">=3.12"`. Commits follow Conventional Commits.

**Ask First:** Adding any dependency beyond `ruff`, `import-linter`, `pytest`. Renaming layer directories or adding a new top-level layer.

**Never:** Implement configuration/DI (Story 1.2) or domain model/schema (Story 1.3). Add SQLAlchemy/Pydantic runtime wiring. Nest packages under a second `src/<pkg>/` level or use namespace-package/sys.path hacks.

## Spec Change Log

## Design Notes

- **Flat `src/<layer>` is fixed by AD-1 + the story AC** — do not introduce a wrapping package (`src/xgplib_workers/...`) even though it avoids generic top-level names.
- **Why import-linter:** Ruff cannot ban imports by source path (its `banned-api`/`flake8-tidy-imports` rules are global). Import-linter's `layers` contract encodes the rule directly:
  ```toml
  [tool.importlinter]
  root_packages = ["domain", "application", "infrastructure"]
  [[tool.importlinter.contracts]]
  name = "Hexagonal dependency rule"
  type = "layers"
  layers = ["infrastructure", "application", "domain"]
  ```
  Listed top-to-bottom as highest→lowest: higher layers may import lower ones, never the reverse.
- **Importability matters:** `root_packages` and pytest both need the `src/` packages importable. Use uv's default hatchling backend with `[tool.hatch.build.targets.wheel] packages = ["src/domain", "src/application", "src/infrastructure"]`; if that does not install cleanly, fall back to setuptools `packages.find where = ["src"]`.
